# Production V8 — 反射強度による白線検出の改善

`8.0.0-production-v8`

反射強度から白線 (実線・破線) がうまく取れない問題に対して、Stage1 の
セル値推定・σ 正規化と、Stage2 の線種判定を修正した。

---

## 1. 何が壊れていたか

実データ (IBEV, 754,622 点 / 走行長 612m) を計測した結果、3 つの独立した
欠陥が重なっていた。

### 1-1. `i_topk` がセル内点数に依存していた (影響最大)

`groupwise_topk_mean(k=3, largest=True)` を、点数が 1〜187 とばらつく
セルに一律に適用していた。点数 1 のセルは「1 点そのもの」、点数 10 の
セルは「上位 3 点の平均」になるため、同じ反射率でもセル値が変わる。

背景セルの残差中央値を点数別に測った実測値:

| セル内点数 | 1 | 2 | 3 | 4 | 5 | 6 | 8 |
|---|---|---|---|---|---|---|---|
| `i_topk` 中央値 | 23.0 | 25.0 | 36.3 | 55.3 | 61.7 | 62.3 | — |
| 背景に対する偏り | −8.3 | −4.2 | −0.5 | +7.5 | +12.5 | +13.4 | +16.9 |

点数だけで 25 カウントの系統誤差が乗る。白線の実際の超過量が 20〜45
カウントなので、信号と同じ大きさの偽信号を注入していたことになる。
点数 3→4 で推定量が「全点平均」から「上位 3 点平均」に切り替わるところ
に段差が出ているのが分かる。

`mean_points_per_cell` は 2.85、occupied セルの 32% は点数 1 だった。

### 1-2. ロバストスケールを回廊全幅で取っていた

`row_robust_scale()` は s 列ごとに d 方向 −15〜+15m 全体の MAD を取る。
ここには歩道・縁石立ち上がり・法面・植栽・停車車両が全部入る。
|d| 帯ごとの MAD 実測:

```
|d| 0-2m: 19.0   2-4m: 13.6   4-6m: 27.8   6-8m: 13.8
       8-10m: 17.0  10-12m: 23.0  12-15m: 17.7     全体: 22.9
```

倍以上ばらついており、全幅スケールが広い帯に引きずられる。各トラック
位置で近傍 3m のみのスケールに置き換えると、白線位置の実効 SNR は
平均 2.11σ → 3.15σ に上がった。

### 1-3. 線種判定が「塗装パターン」ではなく「検出の途切れ」を測っていた

これが「実線・破線がうまく出ない」の直接原因。stage2 の観測列から
オン/オフ長を出すと、**16 本すべてのレーンで median_on が 0.25〜0.75m**
(s 分解能 0.25m の 1〜3 セル) しかなかった。

| idx | 旧ラベル | 生の median_on / off | 1.0m ギャップ閉じた後の on |
|---|---|---|---|
| 5 | Solid | 0.75 / 0.50 m | **15.5 m** |
| 10 | **Dashed** | 0.50 / 0.50 m | **29.0 m 連続1本** (実線) |
| 13 | Solid | 0.75 / 0.38 m | 20.25 m 連続1本 |
| 9 | Dashed | 0.50 / 0.50 m | on 8.0 / off 3.0 m |

`dash_on_min = 0.5`, `dash_off_min = 0.5` だったため、2 セルの検出欠落が
「破線のダッシュ」として受理される。実線と破線の判定が median_off が
1 セルか 2 セルかで決まっており、実質ランダムだった。

## 2. 変更点

### Stage1 (`lanegen_core.build_intensity_sigma`)

一括経路 (`lanegen_stage1_extract`) とストリーミング経路
(`lanegen_streaming`) が同じ処理を重複実装していたので、共通関数に
まとめた上で以下を入れた。既定値は改善後の挙動。

1. **点数バイアス補正** (`count_bias_table`)
   背景セルの残差中央値を点数ごとに取り、セル値から差し引く。塗装セルは
   全体の数 % なので中央値は汚染されない。
2. **点数重み付き annulus 背景** (`annulus_background_weighted`)
   背景をセル値の単純平均ではなく点数重み付き平均にする。セル推定量が
   点数依存である以上、背景側も点単位で平均しないと差分に残る。
3. **s 方向の重み付きプール** (`pool_along_s`, 既定 1.25m)
   白線は s 方向に連続するので、塗装を鈍らせずに 1 セルあたりの実効点数
   を増やせる。d 方向には広げない (塗装幅 0.15m が潰れる)。
   有効セル率が 0.836 → 0.97 に上がる。
4. **2-D 局所ロバストスケール** (`local_robust_scale`, 既定 d±3m × s±25m)
   積分画像で O(nd*ns)。標本が足りない窓は従来の列スケールで埋める。

### Stage2 (`classify_line_type`)

1. ラン長を測る前に検出の途切れを埋める (`--dash-close-gap`, 既定 1.25m)。
2. 最長 ON 区間が全長の一定割合以上なら実線と判定
   (`--solid-max-run-ratio`, 既定 0.6)。
3. 破線は ON 長と周期の変動係数で規則性を要求する
   (`--dash-regularity`, 既定 0.6)。実在の破線は周期が揃うが、検出の
   途切れは揃わない。
4. `--dash-on-min` / `--dash-off-min` の既定を 0.5m → 2.0m。
5. 診断用に生の値 (`raw_median_on_m` 等) と `closed_coverage`,
   `max_on_m`, `on_cv`, `period_cv` を features に追加。

### Stage2 (RGB 補完の自動判定)

総延長と本数だけを見ていたため、線が引けていても中身がスカスカな状態を
見逃していた。実データでは `span_ratio 1.64` / `2.78本/100m` と健全に
見える一方で median coverage 0.66・median ON 長 0.5m まで断片化して
いた。断片化指標を判定条件に追加した
(`--rgb-auto-min-coverage` 0.75, `--rgb-auto-min-on-length` 1.5m)。
RGB コントラストの σ 算出も局所スケールに揃えた (`--rgb-scale-mode`)。

## 3. 効果

### 合成データ (正解あり, `make_synthetic_ibev.py`)

| 項目 | v7 | v8 |
|---|---|---|
| lane recall (main+review) | 0.9196 | **0.9451** |
| lane precision | 1.0 | 0.9963 |
| かすれた線 (d=−5.25) の per-GT recall | 0.912 | **1.0** |
| 破線の ON 長実測 (正解 8.0m) | 4.0 m | **9.0 m** |
| 破線の OFF 長実測 (正解 12.0m) | 11.0 m | 10.9 m |
| 実線 (d=−8.75) の分割 | 2 本 (77.0m + 23.5m) | **1 本 (100.2m)** |

v7 は破線のダッシュ長を実際の半分に測っていた。

### 実データ (IBEV, σ 閾値 1.8 で揃えて比較)

| 項目 | v7 | v8 |
|---|---|---|
| 解析可能セル (`bg_valid`) | 132,401 | **286,876** |
| 反射強度トラックの総延長 | 980 m | **2,040 m** |
| 生の ON 区間長 中央値 | 0.50 m | **1.00 m** |
| 最長 ON 区間 中央値 | 3.1 m | **6.6 m** |

σ 分布は中間の裾が軽く (σ1.8 超えが 6.25% → 5.34%)、極値の裾が重く
なった (p99.9 が 5.04 → 5.46)。閾値付近のノイズが減り、本物の塗装だけ
が強く出る、という狙いどおりの形になっている。

## 4. 互換性

- `PRODUCTION_VERSION` を `8.0.0-production-v8` に上げた。
- **v7 以前の Stage1 NPZ は再利用しない** (`_STAGE1_CACHE_COMPATIBLE_VERSIONS`
  から v5/v6/v7 を外した)。`i_sigma` の正規化が変わっているため、再利用
  すると改善が効かないまま古い証拠で走ってしまう。`--resume` を使って
  いる場合、Stage1 は 1 回だけ再計算される。
- 以下のフラグを全部付けると **v7 と 1 bit 違わない出力**になる。
  合成データと実データの両方で、最終 XML のハッシュ一致を確認済み。

```
--no-intensity-count-debias --no-intensity-weighted-background \
--intensity-scale-mode row --intensity-pool-s 0 \
--dash-close-gap 0 --solid-max-run-ratio 2.0 --dash-regularity 1e9 \
--dash-on-min 0.5 --dash-off-min 0.5 \
--rgb-auto-min-coverage 0 --rgb-auto-min-on-length 0 --rgb-scale-mode row
```

### 回帰テストの変更

`lanegen_regression_test.py` の recall 判定を、本体 XML のみから
**本体 + review XML の和**に変更した。

Stage3 は「低信頼のラインは捨てず review XML へ回す」設計なので、
review にあるラインは検出漏れではない。v8 では合成データのオクルージョン
区間 (d=+1.75 の 55〜80m) にあった誤検出が消えた結果、その線の
`max_gap_m` が 15.5m → 31.25m と**正しく**測れるようになり、
`--review-gap-threshold 30.0` に引っかかって review へ回るようになった。
v7 ではノイズがギャップを分断していたので本体に残っていただけである。

precision は従来どおり本体 XML で測る。加えて review が受け皿になり
すぎていないかを見るため、本体のみの lane recall にも下限を入れた。
